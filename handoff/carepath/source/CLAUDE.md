# CarePath 接手约束

本次任务是接入既有作品集并部署，保持已完成的产品设计。先读 README.md、PRODUCT.md、DESIGN.md，再修改相关文件。

## 产品范围

聚焦「医疗费用文件的理解与求助准备」。五项决策：从眼前文件开始；拆成可确认的小步骤；解释转成下一步行动；人工介入纳入流程；照护者为有明确代办边界的协作者。

首页已有 Problem、五项策略导图、三张紧凑分类卡和一个共享全宽展开区。点击分类展开，再次点击收起。照护协作必须留在首页，以真实手机界面和三阶段选择器展示授权→协助→撤回，并说明双方能力与权限变化。不能只保留导航入口。

不要新增广告口号、对设计师说话的批注或空泛术语。作品集面向招聘者和审阅者；访谈脚本保留合理的参与者语言。研究尚未实施，不得编造研究结果或商业成效。

## 层级与可读性

作品集应保持紧凑、有清晰父子层级：分类约22px、展开子标题18px、正文16px；首页协作章节标题32px、阶段22px、细节18px、正文16px。不要把展开长文塞入窄三栏。

老年人手机界面另有较大字号：核心正文20px，放大模式23px，主要按钮至少62px。不要通过缩小手机正文解决作品集排版问题。保留圆角图像卡、克制的桃色/鼠尾草绿、真实手机原型和设备外同步交互逻辑。

## 代码边界

- 页面入口 `site/index.html` 按顺序加载 Lucide、app.js、v2.js；v2.js 复用并覆盖部分旧逻辑，app.js 不是可直接删掉的废代码。
- 手机业务仅改 `mobile-app/src/Prototype.tsx`、`prototype.css`。先完整阅读 `mobile-app/AGENTS.md`。
- 受保护文件包括 App/main/styles、src/mobile、设备与状态图片、Vite/Worker 配置、prepare-sites-build 脚本。不能修改它们来规避路径或排版问题，不能更新锁值掩盖改动。
- 运行 `npm run verify`：静态资源检查、28个受保护文件校验、4项 Sites Worker 测试。Sites 输出保留兼容性，不代表此项目应发布到旧 Sites 项目。
- 默认目标为 `/carepath/`。资源子路径在最终生成文件中统一处理，包括手机入口、原生设备图片和 CSS 字体；不要直接复制未经组装的 mobile-app/dist/client 到正式目录。
- 保留字体许可证。不要提交 node_modules、真实个人文件、环境变量或凭据。

## 权限

照护者默认无权访问。老人选择 Anna、单份文件/清单范围、可选清单管理，再明确确认。管理权必须依赖清单查看权。照护者不应看到其他档案、修改权限、付款、提交申请或转授权。撤回必须让已打开的照护者文件立即不可见，保留老人已有记录。照护协作和专业人员工作台是不同角色。

原型使用同源 localStorage，无法提供真实跨账号/跨设备权限或安全隔离。不要将其描述为生产级鉴权，也不要为部署演示增加真实医疗数据收集。需要扩展生产服务时另行设计身份、服务端权限、审计和数据处理方案。

## 部署

仓库根首页是综合作品集。保留其现有内容与 CNAME，将本项目放到 `/carepath/` 并按原样式增加入口。使用已有部署流程，先核实 Pages 的实际发布设置。修改域名、替换首页或把交接说明公开到主导航都不在当前目标内。
